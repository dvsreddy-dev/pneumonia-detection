    2. Assist clinicians with a rapid automated second opinion — not replace them
    3. Generalise across different X-ray machines and patient populations
    4. Evaluate honestly using AUC-ROC and recall, not just accuracy
    5. Lay the foundation for a deployable web application in the final report

  • We deliberately prioritise recall over precision. In screening, a false negative (missed pneumonia) is far more dangerous than a false positive (unnecessary follow-up).
  • Accuracy is not our primary metric — a model that always predicts "no pneumonia" scores 77.5% accuracy on this dataset and is completely useless clinically.

    • Dataset

    RSNA Pneumonia Detection Challenge

    Training images  : 26,684 chest X-rays (DICOM format)
Test images      :  3,000 chest X-rays
Image dimensions : 1024 × 1024 pixels, grayscale, uint8

    Three-Class Label Structure

    Source ClassBinary TargetDescription
    Normal0Healthy lungs — clear radiograph
    No Lung Opacity / Not Normal0Abnormal but not pneumonia — hardest class
    Lung Opacity1Pneumonia present
    ⚠️ The "Not Normal" class is the hardest to separate — it contains real pathology (enlarged heart, pleural fluid) that visually mimics pneumonia on X-ray.
  • DICOM (Digital Imaging and Communications in Medicine) is the universal standard for medical images — it bundles pixel data and patient metadata in a single file.
  • The dataset doesn't just split into "pneumonia" vs "normal" — there's a third harder group: patients who have a real chest problem, just not pneumonia.
  • The "Not Normal" class is what makes this a genuinely hard classification problem. An enlarged heart or pleural fluid creates the same white haziness in an X-ray that pneumonia does.
  • DICOM files in this dataset sometimes lack the standard DICM header — we must read them with force=True in pydicom.

    What the Data Actually Looks Like

    MetricValueNote

    The Deduplication Discovery

    Raw CSV:    30,227 rows    →  9,555 pneumonia  (31.6%)  ← WRONG
After dedup: 26,684 patients →  6,012 pneumonia  (22.5%)  ← CORRECT

    Pneumonia patients with multiple bounding box annotations (one per opacity region) appear on multiple rows. Failing to deduplicate overstates prevalence and risks data leakage across train/test splits.

  • The first thing we noticed when loading the data was that the row count and patient count didn't match: 30,227 rows but only 26,684 patients.
  • When a radiologist annotates multiple regions of pneumonia, each region gets its own bounding box row — so the same patient appears 2, 3, or 4 times.
  • If we split on rows instead of patients, the same patient's X-ray could appear in both training and test sets — the model would memorise it. This is data leakage and gives falsely optimistic scores.
  • After deduplication, true pneumonia prevalence is 22.5%, not 31.6%. A meaningful difference that affects class weight computation.

  • Class imbalance is the central challenge of medical classification — the disease you're detecting is less common than not having it.
  • 77.5% accuracy sounds impressive until you realise you achieve it by predicting "no" for everyone. This is why we don't report accuracy as our headline metric.
  • We used two strategies: (1) balanced class weights — penalise missing a pneumonia case 3.4× more; (2) monitor AUC-ROC — a threshold-independent metric that measures discriminative ability.
  • The 44.3% "Not Normal" group is the most insidious part of the negative class. These patients actively look sick on the X-ray. This is where most model errors will occur.
    • Preprocessing

    Building a Clean Training Pipeline

    Step-by-Step Pipeline

    DICOM File (1024×1024, uint8)
      ↓
  pydicom.dcmread(force=True)
      ↓
  Cast to float32
      ↓
  Resize → 128×128 (bilinear)
      ↓
  Normalize: img / img.max()
  Result: [0.0, 1.0]
      ↓
  Add channel dim → (128, 128, 1)
      ↓
  CNN-ready tensor

    Key Decisions

    DecisionRationale
    Per-image normalisationScanner max varies (230–255); global stats introduce bias
    128×128 resizeSpeed for baseline; 224×224 used in final report
    No RGB conversionDICOM is natively grayscale — add channel dim only
    force=True on dcmreadMany files lack standard DICM header

    (Refer to preprocessing_before_after.png)

  • DICOM files are already grayscale — a single intensity channel representing X-ray absorption. We add a channel dimension to match CNN input expectations, not to convert colour.
  • We normalise each image individually (not globally) because different X-ray machines produce different absolute pixel intensities. Global normalisation would introduce scanner-specific bias.
  • Going from 1024×1024 to 128×128 is an 8× reduction per dimension — 64× fewer pixels. This makes training fast but discards most fine texture. The final report uses 224×224 with pretrained models.
  • Some DICOM files in this dataset lack the standard DICM preamble. Without force=True, pydicom raises InvalidDicomError on these files.

df_train, df_temp = train_test_split(patient_df, test_size=0.30, stratify=patient_df["Target"], random_state=42)

  • Patient-level splitting is non-negotiable. Row-level splits on the raw CSV would let the same patient appear in both training and test — the model would memorise rather than generalise.
    • Model Building

    CNN Architecture — From Scratch

    Input128 × 128 × 1
    ↓
    Conv2D(32) + BatchNorm→ MaxPool → 64×64×32
    ↓
    Conv2D(64) + BatchNorm→ MaxPool → 32×32×64
    ↓
    Conv2D(128) + BatchNorm→ MaxPool → 16×16×128
    ↓
    GlobalAveragePooling2D→ (128,)
    ↓
    Dense(256, ReLU)+ Dropout(0.5)
    ↓
    Dense(1, Sigmoid)→ P(pneumonia)

    Why Each Component

    LayerPurpose
    Conv2D (doubling)edges → textures → shapes
    BatchNormStable training, higher LR
    GlobalAvgPoolSpatial compression, less overfit
    Dropout(0.5)Redundant feature learning
    Sigmoid outputThreshold-adjustable at inference
    Total: 126,849 parameters
    ~495 KB — smaller than a smartphone icon
  • This is a deliberately lean architecture — 127K parameters, 495 KB. It was designed to be a reliable baseline, not the final model.
  • The three convolutional blocks follow a classic pattern: as spatial dimension shrinks (64→32→16), feature maps double (32→64→128). Early layers learn edges; later layers combine them into complex patterns like consolidated lung tissue.
  • Global Average Pooling was chosen over Flatten+Dense specifically to reduce overfitting on 18K training images — it compresses each feature map to a single spatial average instead of keeping every value.
  • The sigmoid output gives a probability in [0,1]. We can set any threshold at inference — not locked to 0.5. This is critical for clinical threshold calibration.

  • The model trained for 6 epochs before early stopping triggered. Best checkpoint was Epoch 3, where validation AUC peaked at 0.762.
  • At Epoch 5: val AUC collapses to 0.499 (random chance) while train AUC continues climbing to 0.784 — the signature of overfitting. Val loss simultaneously spikes to 4.26.

  • The overall accuracy is 78%. But a model that always says "no pneumonia" also scores 77.5%. Our 78% is barely above a naive classifier.
  • The pneumonia recall of 0.01 means only 13 out of 902 actual pneumonia patients were detected at threshold=0.5. Clinically catastrophic — 98% miss rate.
  • But AUC of 0.768 tells us the model IS learning. It measures whether the model ranks pneumonia cases higher than negative cases — 0.77 vs 0.50 random means genuine discrimination.
  • The model outputs probabilities like 0.35, 0.40, 0.42 for pneumonia cases — it suspects them but doesn't cross 0.5. Lowering the threshold to 0.25–0.30 would catch many more.

    Understanding ROC-AUC = 0.7676

    Y-axis (True Positive Rate / Recall):
  How many actual pneumonia cases does the model catch?

  How many healthy patients does the model falsely flag?

    Threshold Impact on Clinical Utility

    ThresholdApprox. RecallApprox. FPRClinical Verdict
    0.50 (default)~1%~0%❌ Misses almost all cases
    0.35~50–60%~20%⚠️ Moderate screening
    0.20~75–80%~35%✅ Better for mass screening
    0.10~90%+~55%⚠️ High false alarm rate
    Key insight: The model's learned representations are useful. The threshold choice is a clinical decision, not a model failure.
  • The ROC curve is a picture of the model across ALL possible decision thresholds — every point corresponds to a different threshold.
  • The diagonal line is the random classifier. Our curve bulges toward the top-left corner — that's where we want it.
  • AUC of 0.77 means: given a random pneumonia patient and a random healthy patient, there's a 77% chance the model assigns a higher probability to the pneumonia patient. Meaningful from a 127K-param model in 3 epochs at 128×128.
  • The threshold calibration question is: where on this curve do we operate? Screening prefers high recall — move up the curve, accept more false positives. That trade-off is a clinical and operational decision, not purely a data science one.

    Who Did the Model Get Wrong?

    (Refer to evaluation_plots.png — Confusion Matrix panel)

                      Predicted Negative   Predicted Positive

    The Two Types of Error

    Error TypeCountClinical Consequence
    False Negative (missed pneumonia)~889Patient goes untreated → deterioration, sepsis
    False Positive (healthy flagged)~0Unnecessary follow-up, patient anxiety
    At threshold=0.5, the model makes almost zero false positives but nearly all errors are false negatives — exactly the wrong trade-off for a screening tool. The immediate fix: lower the threshold.
  • At 0.5, the model almost never predicts positive. It is extremely conservative — it barely ever says "this person has pneumonia."
  • A false positive leads to a follow-up scan or blood test — inconvenient and costly, but the patient is fine.
  • A false negative — telling a pneumonia patient they are clear — could mean delayed treatment. In vulnerable patients (elderly, immunocompromised, infants) this can mean ICU admission or death.
  • The optimal operating point for a screening tool is NOT zero false positives. The clinical asymmetry strongly penalises missed cases — so we should accept more false positives to gain recall.
  • The immediate next step, before even retraining, is to lower the threshold and re-evaluate. Free performance gain from existing model weights.

    Why the Baseline Struggles — And Why That's Expected

    LimitationImpact
    128×128 inputLoses fine-grained opacity texture — the very thing that defines pneumonia

    No data augmentationNever sees flipped, rotated, or brightness-varied X-rays
    3-epoch convergenceVery early in the learning curve; early stopping prevented deeper training

    What the Baseline Proves

    ✅ End-to-end pipeline correct ✅ Real signal learned (AUC 0.77 vs 0.50) ✅ Infrastructure handles 26,684 images ✅ Strong baseline for transfer learning to beat
  • This is a baseline — it was never intended to be the final model. Frame the results as a foundation, not a failure.
  • Going from 1024×1024 to 128×128 discards 98.4% of pixel information. The subtle textural patterns in a chest X-ray — faint granularity of early consolidation — get blurred out at this resolution.
  • A model with 127K parameters is tiny. A pretrained ResNet50 has 25M parameters and was trained on 1.2M images. Asking our scratch model to learn chest radiology from 18K images is asking a lot.
  • But AUC 0.77 at all is genuinely meaningful. It confirms the pipeline is correct, the labels are clean, the preprocessing works, and there is learnable signal. Transfer learning can focus on improving performance, not fighting data quality issues.
